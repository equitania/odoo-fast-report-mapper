## Claude's Discretion

The following decisions are documented in CONTEXT.md but were not posed as Captain questions — Claude proposed the approach based on existing patterns:

- **BUG-02 (`self_clean` on `_calculated_fields`):** remove the broken call site at `_report.py:139`. Leave `self_clean()` in `_utils.py` untouched (still needed for `self._fields` deduplication at `_report.py:125`).
- **BUG-03 (`check_dependencies` contract):** add `-> tuple[bool, list[str]]` annotation; add regression test on `map_reports` proving a failing dependency blocks the mapping call.
- **BUG-05 (`prepare_connection`):** use `urlparse(url).hostname` to extract hostname; drop the `url.replace("https:", "")` + slash-strip loops. Keep scheme validation and HTTP plaintext warning. Add `if not hostname: raise ValueError(...)` guard.
- **Regression test style:** mock-based unit tests in the appropriate `tests/test_<module>.py` files, matching existing patterns (`mock_odoorpc` fixture, `_make_connection` / `_setup_env` helpers).
- **Annotation policy:** Phase 1.1 adds annotations only where the fix requires it (BUG-06, BUG-03). Broader annotation work is Phase 2.
- **Within-plan execution order:** TDD where natural, but bug fix and regression test always commit together in one atomic `[FIX]` commit.
- **`_utils.py` split:** no. BUG-05 + BUG-07 both touch `_utils.py`, but the file is not split in Phase 1.1.
- **`from __future__ import annotations`:** not added in Phase 1.1 — Phase 2 D-05 introduces it project-wide. Use direct `dict[str, str]` annotation (Python 3.12+ supports it natively).
