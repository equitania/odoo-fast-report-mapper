<objective>
Fix BUG-08 (CR-02) and BUG-09 (CR-03): two sibling defects in add_field_to_dictionary() at _connection.py:668-670 that cause an AttributeError crash or empty-string dependency pollution when ir.model.fields entries are absent or base-module fields are encountered.

BUG-08: IR_FIELDS.search() can return [] (field not found in ir.model.fields — e.g. a computed field). The code currently calls IR_FIELDS.browse(field_id) unconditionally, then field_obj.modules.replace(...). When field_id is empty, the browse returns a falsy non-string proxy whose .modules attribute is False; False.replace(" ", "") raises AttributeError, aborting the entire collect run mid-loop.

BUG-09: Base-module fields have modules == "". "".replace(" ", "").split(",") yields [""], which survives list(set(...)) dedup and lands in every exported YAML dependency list. On import, check_module("") fires a pointless RPC for the empty string against every Odoo server that ingests the YAML.

Both fixes are atomic: they modify the same three lines (668-670) of the same function. The BUG-08 guard mirrors the BUG-01 skip-and-warn pattern (D-01/D-03 from 01.1-CONTEXT.md). The BUG-09 filter is a one-line list comprehension that discards empty/whitespace-only module names.

Purpose: Prevent AttributeError crash when a field has no ir.model.fields entry; prevent "" pollution in dependency lists for base-module fields.
Output: Patched _connection.py + two regression tests in TestAddFieldToDictionary.
</objective>
