# Phase 01.1 Plan 06: entry_name dict guard Summary

**One-liner**: isinstance+truthy guard on Report.__init__ entry_name raises TypeError at construction time, preventing a Python dict object from silently reaching Odoo's name field as corrupted data.

## What Was Built

### Task 1 — `_report.py` guard

- Changed `entry_name` parameter annotation from unannotated to `dict[str, str]`
- Added isinstance guard as the first statement in `__init__` body:
  ```python
  if not isinstance(entry_name, dict) or not entry_name:
      raise TypeError(
          f"entry_name must be a non-empty dict mapping language codes to names, got {type(entry_name).__name__}"
      )
  ```
- Covers both string inputs and empty-dict inputs with a single condition
- Guard placed before the `calculated_fields is None` / `model_fields is None` checks

### Task 2 — `test_report.py` updates

- `minimal_report` fixture: `entry_name="test_entry"` → `entry_name={"de_DE": "test_entry"}`
- `full_report` fixture: `entry_name="custom_entry"` → `entry_name={"de_DE": "custom_entry", "en_US": "custom_entry"}`
- `test_entry_name_string` renamed to `test_entry_name_dict` with updated assertion
- All inline `Report("a", ...)` / `Report(entry_name="e", ...)` calls fixed across:
  - `TestMutableDefaultArguments` (6 calls)
  - `TestAddFields` (2 calls)
  - `TestAddCalculatedFields` (1 call)
  - `TestAddDependencies` (3 calls)
- Added `TestReportEntryNameGuard` class with 3 regression tests:
  - `test_string_entry_name_raises_type_error`
  - `test_empty_dict_entry_name_raises_type_error`
  - `test_valid_dict_entry_name_accepted`
