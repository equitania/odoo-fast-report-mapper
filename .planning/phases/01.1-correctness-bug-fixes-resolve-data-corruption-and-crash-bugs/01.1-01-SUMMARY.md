# Phase 1.1 Plan 01: Guard add_field_to_dictionary Against Empty IR_MODEL Search — Summary

**One-liner**: IndexError crash in collect loop fixed with `if not model_id` guard that logs a warning and returns early, preventing partial-state data corruption.

## What Was Built

**BUG-01 fix in `odoo_fast_report_mapper/_connection.py`:**

Added a guard at line 665 (between `IR_MODEL.search()` and `IR_FIELDS.search()`) in `add_field_to_dictionary()`:

```python
model_id = IR_MODEL.search([("model", "=", model_name)])
if not model_id:
    logger.warning(f"Model '{model_name}' not found — skipping dependency collection")
    return data_dictionary
field_id = IR_FIELDS.search([("model_id", "=", model_id[0]), ("name", "=", field_name)])
```

**Regression test in `tests/test_connection.py`:**

Added `test_empty_model_search_skips_and_returns_dict` to the existing `TestAddFieldToDictionary` class. Test confirms:
- `ir.model.fields.search` is never called when model not found
- Function returns without raising `IndexError`
- Field tracking still records the entry (field added to dictionary before guard)
