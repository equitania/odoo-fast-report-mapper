## Implementation Decisions

### Error Policy for Empty / Invalid Inputs (BUG-01, BUG-04)

- **D-01 (BUG-01): Skip-and-warn when `IR_MODEL.search()` returns empty in `add_field_to_dictionary`.**
  - **Pattern:** `logger.warning(f"Model '{model_name}' not found — skipping dependency collection")` + early `return data_dictionary`. No exception.
  - **Why:** The collect-flow iterates over many reports × many fields per report. A missing model typically reflects config drift (an Odoo module was uninstalled) — not a hard error. Aborting mid-collect would leave a partial, non-persisted `data_dictionary` and frustrate large migration runs. Pragmatic for production use, and matches the review-suggested fix verbatim.
  - **How to apply:** add the guard at `_connection.py:664-665`. No CLI summary block (D-03). The fix is a defensive skip — call sites do not need to change.

- **D-02 (BUG-04): Fail-loudly with `ValueError` when `build_name_search_domain` receives an empty `name_dict`.**
  - **Pattern:** `if not name_dict: raise ValueError("Cannot build name search domain from empty name_dict")` at the top of the function. No skip, no return-empty.
  - **Why:** Asymmetric with BUG-01 by design. A broken YAML producing an empty `name_dict` is **never** a legitimate state — it would silently match all reports for the model and overwrite the first one found (data corruption in the target Odoo). Hard failure forces the user to fix the YAML before any mapping side-effect occurs. The empty-dict guard in BUG-04 also subsumes the empty-input case for BUG-06 (a Report with empty `entry_name` would never reach `build_name_search_domain`).
  - **How to apply:** add the guard at `_lang_utils.py:69` (top of `build_name_search_domain`), before the `for name in name_dict.values():` loop.

- **D-03 (BUG-01 UX): Log-warning only — no CLI summary block.**
  - **Pattern:** `logger.warning(...)` per skipped model. No aggregated counter in the CLI output ("X models skipped").
  - **Why:** Consistent with the existing logging convention in `_connection.py` (warnings go to the logfile, CLI output stays clean). Users who tail the logfile see everything; users who do not are not reading warnings anyway. Adding a CLI summary block would expand the scope to CLI-output formatting changes — out of Phase 1.1.
  - **How to apply:** plain `logger.warning(f"Model '{model_name}' not found — skipping dependency collection")`. Use the module-level `logger` already imported in `_connection.py`.

- **D-04 (BUG-04 test shape): Unit-test on `build_name_search_domain({})` only — no integration test.**
  - **Pattern:** `pytest.raises(ValueError): build_name_search_domain({})` in `tests/test_lang_utils.py`, inside the existing `TestBuildNameSearchDomain` class.
  - **Why:** The bug surface is the function itself. An integration test through `map_reports` would add mock-surface and slow down the suite without revealing a different failure mode. Existing test structure (`TestBuildNameSearchDomain::test_empty_dict` returns `[]` — that assertion will be **updated** to expect `ValueError` per the new contract).
  - **How to apply:** modify the existing `TestBuildNameSearchDomain` test class or add a new test, depending on whether the empty-dict case is currently asserted as `[]` (verify in plan).

### BUG-07 YAML Auth Fix Scope

- **D-05 (BUG-07): Read both `password` and `api_key` from YAML; api_key wins if both set.**
  - **Pattern:** mirror `_utils.py:436-439` (the env-loader's existing logic):
    ```python
    if yaml_object["Server"].get("api_key"):
        credential = yaml_object["Server"]["api_key"]
        auth_method = "api_key"
    else:
        credential = yaml_object["Server"]["password"]
        auth_method = "password"
    ```
  - **Why:** 1:1 consistency with `create_connection_from_env()`. Backward-compatible for all existing password-only YAMLs (no breaking change). Enables api_key in YAML without requiring users to migrate to `.env`. Honors the established hard-break policy by NOT introducing a deprecation warning here (the v1.0 hard-break is via MIGRATION.md, not runtime warnings — per PROJECT.md Out-of-Scope "DeprecationWarnings für entfernte APIs").
  - **How to apply:** modify `_utils.py:259-281` (`create_odoo_connection_from_yaml_object`) to call `OdooConnection(...)` with the resolved `credential` and `auth_method` keyword arguments. The current positional-arg call (`yaml_object["Server"]["password"]` as the 8th positional argument) must become keyword-based to set `auth_method` explicitly.

- **D-06 (BUG-07 conflict policy): api_key silently wins over password, no warning.**
  - **Pattern:** truthy-check on `api_key` first; if present, `password` is ignored without log/warning.
  - **Why:** Reference behavior is the existing test `test_api_key_wins_over_password_when_both_set` (in `tests/test_utils.py`) which already documents this for the env-loader. Phase 1.1 unifies the two factories' behavior; adding a warning here would create inconsistency between the env-loader (silent) and the YAML-loader (warns).
  - **How to apply:** no additional code beyond D-05.

- **D-07 (BUG-07 docs): YAML schema docs and `yaml_examples/connection_yaml/*` are NOT updated in Phase 1.1.**
  - **Why:** PROJECT.md / REQUIREMENTS.md DOCS-02 explicitly assigns README / SKILL.md / CLAUDE.md / RELEASE_NOTES / template-YAML updates to Phase 4. Phase 1.1 keeps the scope tight: code fix + regression test only.
  - **How to apply:** add a TODO note in Phase 1.1 DISCUSSION-LOG.md cross-referencing Phase 4 DOCS-02 so the docs update is not forgotten when v1.0 RC is cut.

### BUG-06 Enforcement Layer (Report.entry_name)

- **D-08 (BUG-06): Runtime guard in `Report.__init__` + type annotation `dict[str, str]`.**
  - **Pattern:**
    ```python
    def __init__(self, entry_name: dict[str, str], report_name: str, ...):
        if not isinstance(entry_name, dict) or not entry_name:
            raise TypeError(
                f"entry_name must be a non-empty dict mapping language codes to names, "
                f"got {type(entry_name).__name__}"
            )
        ...
        self.entry_name = entry_name
    ```
  - **Why:** Phase 1.1 is a correctness phase, not a type-safety phase. Relying on Phase 2 mypy-strict alone leaves the library vulnerable to PyPI consumers who do not run mypy (Equitania-internal, ownerp-demodata, external partners). A runtime guard fails fast at construction time with a clear message, instead of producing a cryptic `TypeError: string indices must be integers` deep in `self_ensure()`. The annotation gives Phase 2 something to enforce statically without re-touching this code.
  - **How to apply:** modify `_report.py:9-36` (`Report.__init__`). Annotation + isinstance/non-empty check. No property setter (D-09 below).

- **D-09 (BUG-06 depth): Check `isinstance(dict)` + non-empty only — no per-key/per-value validation.**
  - **Pattern:** the guard above is the complete check. No `all(isinstance(k, str) for k in ...)`, no language-code whitelist.
  - **Why:** `_lang_utils.normalize_name_dict()` runs upstream and already normalizes/validates language codes (legacy `ger`/`eng` → `de_DE`/`en_US`). Doubling that validation in `Report.__init__` would be redundant and surface false positives for partner-specific locales (e.g., `fr_BE`). The two realistic failure modes the guard catches: (a) someone passes a `str` instead of a dict, (b) someone passes `{}` from a broken YAML. Both are caught by `isinstance(dict) + truthy`.
  - **How to apply:** see D-08.

### Claude's Discretion (no Captain decision needed)

- **BUG-02 (CR-03): Remove the `self_clean(self._calculated_fields)` call at `_report.py:139`.**
  - **Recommendation:** Option B from the baseline review. Leave `self_clean()` in `_utils.py` untouched (other callers like `_report.py:125` for `self._fields` still need it for list-deduplication). Remove only the broken call site for `_calculated_fields`.
  - **Why:** the calculated-fields structure is `{field_name: {function_name: [params]}}` — the outer keys are already unique (dict semantics), and the inner-dict values must not be flattened. The function `self_clean` exists for the legitimate use case of deduplicating list-valued dict values; calculated-fields is not that shape. Minimal-invasive: zero risk to existing list-valued callers, no signature change.
  - **Test:** assert that a `Report` constructed with `calculated_fields={"eq_get_payment_terms": ["partner_id.lang", "currency_id"]}` retains the inner list after `__init__` (read `report._calculated_fields["eq_get_payment_terms"]` → `["partner_id.lang", "currency_id"]`).

- **BUG-03 (CR-04): Formalize the return-type contract; the bypass surface is already gone.**
  - **State:** `check_dependencies` in `_connection.py:203-217` already returns `tuple[bool, list]`. The single remaining caller at `_connection.py:289` already unpacks the tuple correctly. The original LSP-violation surface (the base class's `map_reports` doing `bool(tuple)`) was eliminated by the Phase 1 consolidation (D-08 from 01-CONTEXT.md inlined `map_reports` as the Eq-version; no base class remains).
  - **Recommendation:** add the explicit return annotation `-> tuple[bool, list[str]]` on `check_dependencies`. Add a regression test that proves a missing dependency stops `map_reports` (mocks `check_module` to return `False` for one dep; asserts the report is not written). This satisfies ROADMAP Success Criterion #3 ("Regression test proves a missing dependency stops the run") without changing the method's behavior.
  - **Why:** the bug is half-fixed by Phase 1 already. The annotation locks the contract for Phase 2 mypy-strict; the regression test ensures no future caller can accidentally re-introduce the bypass.

- **BUG-05 (WR-04): Use `urlparse(url).hostname` to strip both scheme and path.**
  - **Recommendation:** in `_utils.py:69-107` (`prepare_connection`), replace the existing scheme/path-stripping logic with `parsed = urlparse(url); hostname = parsed.hostname`. Keep the existing scheme validation (already present), HTTP plaintext warning, and port-derivation logic. Drop the `url.replace("https:", "")` and the leading-slash / trailing-slash / trailing-backslash strip loops (the urlparse output is already clean).
  - **Why:** the current code already calls `urlparse(url)` to validate the scheme; using `parsed.hostname` instead of the legacy string-replace is mechanical. `urlparse(url).hostname` returns `None` for malformed URLs — add `if not hostname: raise ValueError(f"Cannot parse hostname from URL: {url!r}")` to keep the loud-failure contract.
  - **Test:** unit-test on `prepare_connection("https://host/web", 443)` asserts the resulting `ODOO(url=...)` is called with `url="host"`, not `url="host/web"`. Use the existing `mock_odoorpc` fixture from `conftest.py:185-196`.

- **Regression test style:** mock-based unit tests in the appropriate `tests/test_<module>.py` file, matching the existing pattern (see `TestCheckDependencies` and the `_make_connection` / `_setup_env` helpers in `test_connection.py`). One new test per bug minimum.

- **Annotation policy:** Phase 1.1 adds annotations **only** where the bug fix requires it (BUG-06 dict[str, str], BUG-03 tuple[bool, list[str]]). Broader annotation work is deferred to Phase 2 — do not opportunistically annotate other functions touched by the bug fixes.

- **D-10: One plan per bug = 7 plans total. Severity-first ordering. No pre-flight plan. Standard `gsd-verify` after all plans.**
  - **Plan filenames (severity-first per BASELINE-REVIEW order):**
    - `01-01-PLAN.md` → BUG-01 (CR-02) — `add_field_to_dictionary` IndexError guard
