# Phase 1.1 Plan 07: API Key Auth in create_odoo_connection_from_yaml_object Summary

**One-liner:** Fixed BUG-07 — `create_odoo_connection_from_yaml_object` now honors `api_key` from YAML Server config by checking `server.get("api_key")` first and passing `auth_method=auth_method` to `OdooConnection()`, mirroring `create_connection_from_env` behavior.

## What Was Built

### Task 1: _utils.py fix (BUG-07)

`create_odoo_connection_from_yaml_object` previously hardcoded `auth_method='password'` by always passing `yaml_object["Server"]["password"]` directly to `OdooConnection`. The fix:

1. Introduces `server = yaml_object["Server"]` local variable to reduce lookup repetition.
2. Adds api_key precedence block: `if server.get("api_key"): credential = server["api_key"]; auth_method = "api_key"` else falls back to `password`.
3. Passes `auth_method=auth_method` as keyword argument to `OdooConnection()` (consistent with the existing `create_connection_from_env` call pattern at line 493–504).
4. No warning logged when both `api_key` and `password` are present — silent api_key wins per D-06.

### Task 2: Regression tests (TestCreateConnectionFromYamlObject)

Three tests added to `tests/test_utils.py` using `mock_odoorpc` and `sample_connection_yaml_data` fixtures:

- `test_api_key_sets_auth_method_api_key`: api_key present → `auth_method == "api_key"`, `password == "my-api-key"`
- `test_password_only_sets_auth_method_password`: no api_key → `auth_method == "password"`, `password == "test_password"`
- `test_api_key_wins_when_both_set`: both present → `auth_method == "api_key"`, `password == "api-key-wins"`
